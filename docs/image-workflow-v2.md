# 图片仿写工作流 V2：分析与建议方案

更新：2026-10-14。图片仿写位于当前仿写项目内部，与文案编辑、视频仿写、素材库平级。当前编排规则版本为 6，建议方案规则版本为 1。

## 产品行为

流程为“选图与方案 → 审阅提示词 → 审阅结果”。用户选择一张被仿写图，可以添加至多两张辅助图，也可以不添加。点击底部“分析图片”，系统分析全部已选图片，并使用文本模型提出三个有实质差异的建议。用户主动选择其中一个，填写可选附加要求，再点击“生成提示词”。提示词审阅、明确提交生图、结果保存与采用沿用现有流程。

三个建议根据实际图片生成，包含标题、保留与修改内容说明及内部来源控制，不使用固定题材或固定三套模板。没有参考图也返回三个方案；系统不默认替用户选中。附加要求最多1000字，可以留空；明确的附加修改优先于建议方案对应的基础设定，其他部分继续遵循已选方案。

分析和建议均缓存：图片内容、图片顺序、分析资料、视觉及文本模型配置、规则版本一致时可复用。更换图片清除旧建议和选择，需要重新分析；修改比例、清晰度或数量不会清除建议。更换比例、选择建议或修改附加要求会使提示词过期。分析或文本建议失败保留已完成的视觉分析，重试不重复分析有效图片。打开页面、切换草稿不触发模型。

内部仍使用八项来源控制，供模型编排与历史回溯：

| 维度 | 管理的内容 |
| --- | --- |
| 主体与对象 `subject` | 人物、物体、数量、身份与关键外形 |
| 动作与关系 `action` | 姿态、动作、表情及对象间互动 |
| 场景与背景 `scene` | 环境、背景对象与装饰 |
| 布局与视角 `composition` | 位置、比例、视角、层次与留白 |
| 配色 `palette` | 全局色板、颜色分工与对比 |
| 光影 `lighting` | 光源、明暗与阴影 |
| 画法与质感 `texture` | 摄影或绘制方式、笔触、表面表现 |
| 文字版式 `text` | 有意义的文字与排版；不默认复制水印 |

建议方案在内部为各项指定图片来源、自定义要求或自动设计。前端已移除逐项来源矩阵，改为三个建议卡片和附加要求框。旧版逐项控制接口保持兼容，历史生成依据保持原样。

分析包含独立的主体与动作维度。界面展示建议说明，无需用户逐项编辑模型分析报告。分析建议阶段需要配置视觉及文本模型，不调用图片生成模型。

主图从本笔记或本项目素材中选取；辅助图还可来自官方图库。选择窗口提供完整缩略图预览、筛选、搜索及上传。官方素材选用时保存项目快照；本阶段不填充官方图库。上传只进入项目素材库，不自动加入发布素材。

替换或移除图片后，原建议不可继续用于编排；允许保存未完成草稿。选中建议由后端验证并绑定其持久化来源，拒绝过期建议或不存在的标识。

## 提示词与实际输入

`feature_controls` 记录所选建议的基础来源；`extra_requirements` 记录用户明确的附加修改。编排同时接收这两部分及建议说明、实际图片编号和画幅。图片分析、旧风格字段、笔记正文和未保存文案不能覆盖用户选择。

仅实际贡献图片维度的图片传入语言模型及图片模型，按主图、辅助图的稳定顺序排列并重新编号。没有贡献的主图也不发送；主图 ID 仅保留为采用位置。全部自定义或自动设计时不发送任何图片，使用同一尺寸与回执机制进行文生图。

图中文字独立大组件已移除。选择某图的文字版式时，该图已有识别文字可作为资料进入该维度；不自动读取其他图片或旧全局 `image_text`。自定义文字维度可要求添加、替换、删除文案或调整版式。自动文字维度默认不添加、复制或编造文字和水印。分析与 OCR 是不可信资料，不能改变系统契约。

语言模型返回八项最终画面描述、原样来源控制及冲突列表。服务端检查结构、来源绑定、长度及未解决冲突，再按固定顺序整理为唯一完整提示词。新路径不使用特定人物、色彩词汇或逐字复述作为通过条件。结构校验不能证明语义正确，也不能代替用户审阅或最终图片质量验收。不能同时满足的要求需提示用户修改，不自行覆盖选择。

用户可编辑完整提示词。修改图片、建议选择、附加要求或比例会使提示词过期；只修改数量或清晰度不需要重新调用语言模型。文本模型在明确点击分析图片（生成建议）或编排提示词时调用，图片模型仅在审阅后点击“确认并生成 N 张”时调用。实际提交与审阅文本一致，显式设置 `prompt_extend:false`。生成历史保存当时的建议、附加要求与原始提示词。

## 界面与保存

笔记加入仿写库时，按原笔记顺序为每张已就绪图片创建独立草稿：第一张对应方案 1，之后依次编号。打开图片仿写默认进入方案 1；后台轮询保留用户当前选择，手动新建后进入新方案。初始化不分析图片、不编排提示词、不生图。

没有图片方案的旧项目在打开图片仿写时补齐。初始化接口幂等，已有方案保持原样；失败显示重试入口，避免后台轮询反复写入。没有就绪图片时保留选图入口，图片就绪后可初始化。草稿数量、主图绑定、文案版本和发布素材分别管理。

紧凑工具行放置图片草稿切换与新方案，三阶段导航位于其下。宽屏图片和三个建议分别横排，窄屏纵排；图片完整显示，不裁切关键内容。建议卡片展示标题和具体修改说明，下方提供可留空的附加要求框。底部操作栏位于工作区布局槽，占用真实高度并与窗口底部对齐；正文在上方滚动，随侧栏和窗口宽度调整。

普通修改延迟 600ms 自动保存。切换方案、编排和生成前等待保存完成。失败保留本地编辑并阻止提交，可重试。未保存文案不阻止图片模块，也不被图片操作覆盖。

## 输出与结果

默认 3:4、标准、1 张；数量 1–4 张。

| 比例 | 标准 | 高清 |
| --- | --- | --- |
| 3:4 | 960 × 1280 | 1536 × 2048 |
| 1:1 | 1024 × 1024 | 2048 × 2048 |
| 9:16 | 720 × 1280 | 1152 × 2048 |

成功图片自动保存到本项目素材库，默认未采用。用户采用时只替换主图对应发布素材位置，保留其他素材、顺序、文案与未勾选状态。历史结果按本次不可变快照展示原始控制、图片顺序、提示词和输出设置，不用当前编辑内容推断历史。

批次串行执行单张请求，每张 `n:1`。明确失败暂停剩余任务，成功图片保留。提交结果不明时禁止自动重投，重启后优先使用持久化回执恢复下载。实际尺寸异常的有效图片仍保存并提示，不自动重画。

## 数据模型

```json
{
  "workflow_version": 2,
  "primary_asset_id": "采用时的替换位置",
  "references": [{"asset_id": "辅助图ID"}],
  "edit_intent": {"mode": "flexible"},
  "proposals": [{"id": "proposal-1", "title": "基于实际图片的建议", "summary": "具体说明保留和修改内容", "feature_controls": {"...": "以下八维完整控制"}}],
  "proposals_input_digest": "三个建议共同对应的图片及分析依据摘要",
  "selected_proposal_id": "proposal-1",
  "extra_requirements": "用户可选补充内容",
  "feature_controls": {
    "subject": {"mode": "image", "asset_id": "主图ID"},
    "action": {"mode": "image", "asset_id": "辅助图ID"},
    "scene": {"mode": "auto"},
    "composition": {"mode": "image", "asset_id": "主图ID"},
    "palette": {"mode": "custom", "value": "用户自行填写的配色要求"},
    "lighting": {"mode": "auto"},
    "texture": {"mode": "custom", "value": "用户自行填写的画法要求"},
    "text": {"mode": "custom", "value": "不添加文字"}
  },
  "output": {"ratio": "3:4", "clarity": "standard", "count": 1},
  "prompt": "用户审阅的最终提示词",
  "prompt_input_digest": "输入依据摘要",
  "prompt_rules_version": 6,
  "revision": 3
}
```

每项恰为 `image`、`custom`、`auto` 之一。图片来源只能是当前方案中的图片；自定义不能残留图片 ID；自动设计不能残留图片或自定义值。草稿允许尚未填写的自定义值或图片来源，正式操作严格检查完整性。兼容字段 `feature_sources` 由图片控制派生，不能形成第二套依据。

分析缓存按图片内容哈希、视觉模型及地址、规则版本 `visual-features-v2.4-flexible` 区分。旧报告和历史结果保留，不伪造动作字段或自动消耗模型调用。批次与结果保存深拷贝后的 `feature_controls`、实际输入 ID、哈希、最终提示词、模型、输出、修订和规则版本。

个人图片只在所属工作区、项目可用。删除引用检查覆盖当前方案、批次、历史结果、任务快照、文案版本和发布稿；仍被引用的文件不能单独删除。

生成成功只保存到项目素材库，不会自动出现在发布素材候选中。“采用此图”明确替换主图；素材库的“加入发布素材”明确追加到发布草稿，保存和确认后再创建发布稿。仅用于参考的上传图也不会自动进入发布选择。版本对比入口仅位于文案编辑页签。

素材库提供删除确认；删除后从库及新选图候选移除，已有生成历史和发布内容保留。此操作记录 `asset.library_deleted_at`，不绕过原有文件引用保护。选图搜索只匹配名称、现有识别文字、视觉分析和图库标签，分辨率只用于展示；过滤和取消窗口不更改保存的选图。

## 接口与持久化任务

统一前缀 `/api/v1`，请求携带 `platform=xiaohongshu`；写操作沿用 CSRF 校验。

| 接口 | 内容 |
| --- | --- |
| GET `/image-capabilities` | 配置状态、支持的尺寸与数量、提示词及建议规则版本、`proposal_count:3`；不含密钥 |
| POST `/rewrites/:id/images` | `{workflow_version:2,version_id,primary_asset_id,references?}`；新建 flexible 草稿，不调用模型 |
| PATCH `/rewrites/:id/images/:image_id` | `{revision,primary_asset_id?,references?,selected_proposal_id?,extra_requirements?,output?,prompt?}`；选择服务器保存的建议，自动保存并返回新修订；旧版 `feature_controls` 接口兼容 |
| POST `/rewrites/:id/images/:image_id/analyze` | `{revision,suggest_proposals:true}`；分析全部已选图片并给出三个建议，保留已完成的分析缓存；旧版 `{revision,asset_id?}` 仅做特征分析 |
| POST `/rewrites/:id/images/:image_id/compose-prompt` | `{revision}`；持久化文本编排任务 |
| POST `/rewrites/:id/images/:image_id/generate` | `{revision,prompt,request_id}`；请求 ID 去重，返回批次与任务 |
| POST `/rewrites/:id/images/:image_id/batches/:batch_id/resume` | 明确失败重试、恢复下载、继续或取消；未知提交需先核实 |
| POST `/rewrites/:id/images/:image_id/apply` | `{asset_id,version_id?}`；只替换对应主图位置 |
| GET `/rewrites/:id`、GET `/jobs` | 关闭页面后恢复方案、批次与任务状态 |
| GET `/media-library?rewrite_id=:id` | 当前项目生成结果和上传素材 |
| DELETE `/rewrites/:id/media-library/:asset_id` | `{confirm:true}`；项目内素材库删除，保留已有引用与文件，重复调用幂等 |

修订、输入哈希、提示词依据、模型配置或规则版本过期时返回冲突。未处理完的批次阻止再次提交。正式请求前记录 submitting；供应商标识、地址或编码先持久化，再下载保存。通用重试不绕过未知结果保护。

## 旧方案兼容

旧七维自由组合、保留内容方案和最早的旧版方案均保持原样可查。新版界面对旧方案提供“以此创建新版方案”：保留原图选择，新建可分析建议的草稿，不改写旧方案、提示词、批次或结果，不自动分析、编排或生图。历史恢复下载继续使用原快照。

既有客户端的旧 API 分支仍保留，但新界面只编辑 flexible 方案。不要将过去规则 5 的真实生图记录当作规则 6 的质量证明。
