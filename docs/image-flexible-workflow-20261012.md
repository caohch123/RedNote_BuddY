# 图片仿写逐项控制：实现与验收

日期：2026-10-12。对应“只能满足一个测试用例、用户没有选择自由度”的反馈。完整产品行为和接口见 [工作流说明](image-workflow-v2.md)。

## 问题复盘

上轮将保留主图、蓝白、数字插画等具体测试目标写成固定模式、快捷项和词汇校验。锁定主体、场景、布局和文字限制了其他用途，主体与动作合在一项也无法表达跨图片借用姿势。末尾补充外观优先级不能化解多份旧报告之间的冲突。

本轮用一套逐维度控制替代新界面的模式分支。主图只确定采用位置；八个维度分别选择图片来源、自定义或交给模型，没有必保留主图维度。保留原主体改外观、借用另一主体、独立改变动作、产品图与风景图、全部自定义均走同一流程。

## 完成的改动

- 主体与对象、动作与关系、场景与背景、布局与视角、配色、光影、画法与质感、文字版式八项独立控制，所有选择解锁。
- 删除固定画法／配色快捷项、全局保留模式及独立 OCR 确认组件。自定义按需展开，最多 500 字。
- `feature_controls` 为唯一新依据，服务端派生图片来源。不贡献特征的主图、辅助图及维度不会发送给编排或生图模型；无贡献图时支持零图片请求。
- 先生成八项最终画面要求和冲突清单，验证来源绑定与结构后整理为唯一提示词。不再以固定颜色、角色词或逐字重述分析作为通用质量证明。
- 修改来源、自定义或比例使提示词过期；数量与清晰度只改变输出。未知结果仍禁止自动重投，回执恢复不重复付费请求。
- 未完成草稿可保存，正式操作阻止空来源、空自定义。移除或更换图片后明确要求重新选择，不自动替用户改变来源。
- 新分析拆分主体与动作并升级缓存；整体分析只处理实际贡献图，有效缓存复用。已有同内容图片的人工识别文字保留，不写入共享缓存。
- 批次、结果保存控制项深拷贝与实际图片编号；旧方案、提示词和历史不改写。用户明确点击“以此创建新版方案”才进入新编辑器。
- 未保存的语义修改立即将旧结果归入历史并撤下采用按钮；采用前再次核对替换位置，防止换图与保存的时序冲突。
- 删除引用检查增加历史批次和任务中未参与实际输入的主图锚点。

## 实际画面验收边界与后续

本轮证明的是用户控制、数据来源、提示词与实际提交的一致性，以及失败恢复机制；未声称新规则已通过真实图片质量验收。模型可能错误理解姿态、混合材质或遗漏细节，用户仍需审阅提示词及产物。冲突检测的结构检查也不能证明任意自然语言要求在视觉上兼容。

下一轮真实验收应选择不同题材和修改目的，分别记录主体身份、动作、布局、配色、画法与文字的符合程度。每个具体方案由用户核对后少量生成，不自动重画。规则 5 的 [历史真实测试](image-preserve-content-real-test-20261012.md) 保留为过去记录，不计入规则 6 的质量结论。
