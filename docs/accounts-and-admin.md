# 用户端与管理员端

工作台现在提供两个独立入口，共用一套前后端代码和启动脚本：

| 入口 | 默认地址 | 用途 |
| --- | --- | --- |
| 用户端 | http://127.0.0.1:8080/ | 采集、文案、图片与视频仿写、素材和发布、个人用量 |
| 管理员端 | http://127.0.0.1:8080/admin | 账号、模型服务、跨用户用量、任务和审计 |

管理员账号不拥有创作工作区。用户端与管理端使用不同的会话 Cookie，可以在同一浏览器同时登录。

## 首次登录

后端第一次启动创建 `user` 和 `admin` 两个账号，分别使用随机初始密码。凭据保存在本机 `data/initial-accounts.txt`，不会写入源码、日志或提交到仓库。首次登录必须修改密码，随后才能访问业务功能。密码至少 12 个字符，UTF-8 编码最多 72 字节。

重启服务保留原账号和密码，不会重新初始化。新增账号由管理员创建，初始密码只在创建结果中显示；重置密码会撤销该账号旧会话，并要求重新设置密码。请妥善保管本机初始凭据文件，修改初始密码后可自行移除它。

## 数据归属

- 原有 `data/workbench.db`、素材和小红书登录状态归初始 `user` 账号，文件保持原位置。
- 新用户使用独立的 `data/accounts/<用户ID>/workbench.db` 和媒体目录。数据库、项目、素材、任务、采集 Cookie、小红书会话及用量账本均隔离。
- 管理员可以查看各用户任务的状态和用量，不通过用户内容接口访问创作文案或媒体。
- 模型服务配置、工具路径和计费单价由管理员统一维护；用户只能修改自己的密码、采集 Cookie 和小红书登录状态。
- 身份、会话、限额计数和审计记录存放在 `data/identity.db`。完整备份需要包含整个 `data/`，仅备份原业务数据库不足以恢复新增账号。

## 管理员功能

总览显示当日请求、已报告 Token、估算费用、任务情况及按用户统计。用户管理支持创建成员或管理员、调整显示名称、停用与启用、重置密码、设置每日模型请求上限和并发数。不能停用当前登录管理员，至少保留一个启用的管理员。

模型设置支持各能力的服务地址、模型、工作空间及密钥。已保存密钥仅显示掩码，留空保留原值；清除需要显式操作。接口不会返回模型密钥、用户 Cookie 或任务中的服务凭据快照。

用量面板支持时间、用户、模型和功能筛选、趋势图、详细记录和 CSV 导出。费用按管理员手动配置的单价估算，不代表供应商实际账单。供应商未返回 Token 时显示未报告，不使用字符数推算。图片和视频的张数、秒数单独记录；详见 [计费面板](billing.md)。

任务页面支持查看各用户的处理状态、安全重试，以及取消尚未执行的排队任务。发布任务和提交结果不明的任务需要用户核实，不允许管理员直接重投。停用用户会撤销登录、停止本地运行任务并暂停新的队列领取；已经被外部供应商接受的任务可能仍在供应商侧执行与计费。

审计记录登录、改密、账号管理、模型和单价修改、任务管理操作，不保存密码、密钥、Cookie 或创作正文。

## 限额口径

每日请求额度按北京时间自然日统计，`0` 表示不限制。额度在实际模型请求发出前原子预留，连接失败或结果未知也占一次尝试，避免重试绕过限额；仅被并发限制等待、参数校验失败或未配置模型的请求不占用额度。进程重启保留每日计数。并发数范围为 1–8。

限额覆盖文案、视觉分析、OCR、ASR、图片生成及视频提交。连接检查、视频任务状态轮询和素材下载不计入新的模型请求。一个后台任务可能包含多次模型请求，因此请求额度与后台任务数不同。当前提供请求限额，不提供严格的预付费余额、Token 预算或在线支付。

## 会话与运行范围

密码使用 bcrypt 哈希。浏览器持有随机的 HttpOnly、SameSite=Strict 会话 Cookie；数据库只保存会话令牌哈希。写请求绑定会话 CSRF，登录成功及修改密码后轮换会话。会话最长 12 小时，闲置 30 分钟失效；单账号连续登录失败会受到限流。

这次交付继续绑定本机回环地址，并保留精确 Host/Origin 限制。它可在本机验证两端与多账号工作流。公网服务还需要 HTTPS、独立部署与密钥管理、生产限流、备份恢复演练及监控；不能仅把监听地址改为公网就作为线上版本使用。

## 主要接口

先用 `GET /api/v1/session?realm=user` 或 `realm=admin` 初始化对应会话，保留返回的 Cookie 和 `csrf_token`。登录、改密和其他写请求携带 `X-CSRF-Token`。跨端请求不会复用另一端的角色权限。

| 方法与路径（基于 `/api/v1`） | 功能 |
| --- | --- |
| GET `/auth/me`、POST `/auth/login`、POST `/auth/logout` | 用户身份与登录退出 |
| POST `/auth/password` | `{current_password,new_password}` |
| GET/POST `/admin/auth/...` | 对应的管理员身份、登录退出及改密 |
| GET/POST `/admin/users` | 用户列表与创建 |
| PATCH `/admin/users/:id` | 状态、名称、每日请求上限与并发数 |
| POST `/admin/users/:id/reset-password` | 随机新密码，并撤销旧会话 |
| GET `/admin/overview` | 管理总览 |
| GET/PATCH `/admin/models` | 平台服务与工具配置 |
| GET `/admin/billing`、GET `/admin/billing/export` | 跨用户用量，支持 `user_id` 筛选 |
| PUT `/admin/billing/prices` | 维护全局估算单价 |
| GET `/admin/jobs` | 脱敏任务列表 |
| POST `/admin/users/:id/jobs/:job/retry`、`/cancel` | 安全重试或取消 |
| GET `/admin/audit` | 最近 500 条审计记录 |

用户端已有资源 API 保留，但要求有效成员会话。`PATCH /settings` 仅允许 `{cookie}`，显式空字符串可清除；模型和工具配置改用管理员接口。公开 `/health` 只提供最小存活状态，避免未登录暴露依赖详情。
