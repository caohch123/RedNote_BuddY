# 图片特征来源与底部操作栏修复记录

日期：2026-10-11。范围：小红书仿写项目的图片工作流。未新增供应商，未发起真实模型调用或再次生图。

## 问题与证据

用户在方案 6 中选择辅助图的少女作为主体，主图提供红棕背景、构图、色彩、光线与风格，但结果仍是书本。

只读检查实际方案、编排任务和生成批次后确认：两张图及其哈希都传入了生图任务，编排与生成的输入摘要一致。问题发生在提示词内容：旧系统指令要求“不把辅助图片的主体…自动复制”，与用户显式选择辅助主体矛盾；最终提示词反而排除了人物、猫耳、女仆装等元素。旧 OCR 文字又被追加为必须呈现的文字，产生了水印残留。

原底栏使用卡片内 `position: sticky`，受到父容器边界及底部内边距限制，无法稳定贴到窗口底边。旧测试仅判断按钮未超出窗口，没有验证贴底。

## 修复

- 编排按每个维度的唯一来源处理。`subject` 决定主体，即使来源是辅助图；背景中的“无其他元素”只限制背景，颜色、材质中的旧主体不得替换已选主体。
- 编排模型返回 `feature_sources` 图片编号映射，服务端核对其与实际输入顺序一致。所选主体描述必须完整保留；明显直接否定完整主体描述时拒绝编排，保留输入，不自动重试。此为保守完整性检查，不能替代全面语义审阅。
- 删除“图中文字”组件及其前端状态和限制。新编排不读取旧 `image_text`、`recognized_text`，不追加旧 OCR；分析不再额外调用完整 OCR。旧文字排版报告中的引号内容与已知 OCR 行会清理，保留字体和对齐描述。长旧 OCR 不再阻塞流程。
- 采用 `prompt_rules_version: 3`。旧提示词保留可查看，重新编排前禁止新生图；历史批次及已返回结果按原快照处理，不自动重画。
- 编排输入持久化到任务快照；批次与结果保存独立的特征来源和规则版本。历史记录缺少来源时明确标注，不拿当前选择补写历史。
- 操作栏移入工作区底部布局槽，占用真实空间。正文滚动区止于栏顶部，栏宽跟随内容列，切标签、页面、侧栏或工作区时正确撤下或恢复。

## 验证

### Go 与前端

- `go test ./...` 通过；随后针对最终新增的直接否定、旧排版文字及长旧 OCR 兼容修复，再运行图片工作流和编排专项测试通过。
- Go 模拟服务覆盖异质主辅图、来源编号、实际输入图片顺序、提示词原样提交、`prompt_extend: false`、旧规则拒绝、错误输入保留、历史来源不可变，以及无自动模型重试。
- 前端 10 项单元测试通过，生产构建通过。

### Microsoft Edge

`image-rewrite.spec.ts` 与 `image-action-dock.spec.ts` 最终合计 30 项回归，覆盖：

- 书本主图与少女辅助图的不同特征，主体来自辅助、背景来自主图；取消的特征不会留在请求中。
- 旧 OCR 不自动进入新编排；没有图中文字组件；旧规则提示词禁止直接生成。
- 上游修改使提示词待更新；保存失败保留编辑并阻止生图；数量、清晰度变更不重复编排。
- 采用只替换主图，保留其他素材及未保存文案；历史来源不随当前选择改变。
- 结果不明暂停、旧方案只读、工作区隔离、大尺寸方图/竖图/横图预览边界。
- 1536、825、597、569 × 751 下，页面顶部、中段、底部均验证操作栏底边与窗口底边差不超过 1px；正文底边等于操作栏顶部；按钮可点击、不覆盖侧栏、最后一项特征可滚至栏上方，无新增整页嵌套滚动。

实际网站另以 Edge 只读核验方案 6：四种窗口宽度的图片边界和底栏位置通过；旧提示词刷新后仍保留但生成按钮禁用；已删除文字组件；页面无运行错误、没有任何写请求或模型调用。证据位于 `data/verification/image-reference-live-edge-20261011/`。

最终模拟回归证据：`data/verification/image-reference-final-edge-20261011/`。布局专项日志：`data/verification/footer-regression-edge.log`。

## 部署与使用

已更新本地 8080 工作台，采集服务保持原进程。现有方案、选图、特征映射和历史图片均未被测试修改。

刷新 Edge 后，方案 6 需要先点击“生成提示词”或“重新编排提示词”，核对主体来自辅助图及背景来自主图，再明确确认生图。本轮没有进行真实图片质量复测，仍需审阅实际提示词和新结果，不以模拟接口成功替代成图质量合格。
