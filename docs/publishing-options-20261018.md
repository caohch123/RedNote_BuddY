# 发布方案调研（2026-10-18）

结论：当前桌面工作台优先采用“本地准备发布包 → 官方创作平台人工核对并提交 → 保存发布记录”。后续评估官方小程序发布能力或经平台确认的合作渠道。现有第三方协议发布不作为长期默认方案。本文是调研和改造建议，本次没有修改发布逻辑或提交真实笔记。

## 项目现状

`publisher/bridge.py` 使用随项目固定的 Spider_XHS，二维码登录后保存账号会话，通过第三方签名逻辑上传媒体，并向创作平台的 `/web_api/sns/v2/note` 提交请求。该流程没有使用官方开放平台签发给本项目的应用发布权限。扫码完成登录不等于获得官方开放 API 授权。

现有系统已经实现 Windows DPAPI 加密会话、前后端角色隔离、发布稿与媒体哈希校验、五分钟单次确认令牌、最终提交不自动重试以及提交结果不明时暂停。这些控制降低泄密、误操作和重复提交风险，但不能保证平台一直接受模拟请求，也不能据此判断平台此前具体依据什么识别自动化。

## 方案比较

| 方案 | 本项目的适配性 | 主要边界 |
| --- | --- | --- |
| 导出素材与复制文案，官方页面人工发布 | 当前首选；已有发布包导出、创作平台入口和记录发布结果功能 | 需要人工上传及最终确认，工作台不能把“已导出”当作“已发布” |
| 本机可见浏览器辅助填表，人工提交 | 可作为可选便利功能评估 | 页面变化会影响自动化，仍可能被识别；可见浏览器和人工最后点击不能保证平台批准此种集成 |
| 官方 SDK、小程序发布能力或经核实的合作接口 | 长期优先评估 | 需确认主体资质、申请状态、账号范围、媒体支持与结果语义；不同产品能力不能混用 |
| 继续第三方协议直接发布 | 改造量小，长期可靠性较弱 | 依赖会话、签名与平台私有协议，接口变化和风控可能导致失败；没有免封保证 |

## 官方渠道核查

1. **分享 SDK**：官方 JS SDK 文档支持将图片、视频交给小红书 App 发布，要求登记应用并通过审核。文档明确提醒不再支持自动填充标题、文案、话题。JS 方案的媒体需要服务器地址，不能直接传当前工作台的本地文件。官方分享平台首页当前显示“暂停接入”，因此不能把它作为立即可开通的交付依赖。详情：[JS SDK](https://agora.xiaohongshu.com/doc/js)、[常见问题](https://agora.xiaohongshu.com/doc/qa)、[接入首页](https://agora.xiaohongshu.com/)。

2. **小程序发布**：官方小程序介绍列出“发小红书组件”，说明可将图片或视频、文本和话题传给发布器。这属于小程序内能力，需要按主体、类目、备案、开发与审核流程确认资格，不能直接当作桌面 Go 服务的无人值守发布 API。详情：[小程序介绍](https://miniapp.xiaohongshu.com/doc/DC137160)、[小程序平台](https://miniapp.xiaohongshu.com/)。

3. **小工具容器**：2026-10-13 更新的官方文档列出 `window.xhs.miniTool.postNote`，可携带标题、正文及图文、视频，用户仍可在官方发布页编辑或取消。容器禁止直接请求外部服务，不能直接连接目前的 Go API；需要独立产品适配。其成功回调也不代表笔记最终审核通过。详情：[小工具能力文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)。

此次公开资料调研未核实到面向普通个人账号、可普遍申请且支持任意账号无人值守发布的官方服务端 API。这不表示不存在定向合作或受限权限，应通过官方工单进一步确认。市场工具自称“API 发布”“官方合作”，不足以证明其取得了本业务所需的发布权限；应核对应用身份、授权页面、具体权限与数据保留方式。

## 建议的改造范围

- 默认提供“导出发布包”“复制文案”“打开官方创作平台”“记录发布结果”，保留图文与视频支持。
- 将现有直接发布通道设为管理员控制的可选能力，而非用户端默认入口。关闭时由后端禁止调用，已有结果不明的记录仍保留供核实。
- 发布稿绑定用户、目标账号、文案版本、媒体顺序、封面及文件哈希；发生变化需要重新确认。
- 区分“已准备”“已交接”“待核实”“已记录发布”“审核状态”。打开页面、完成上传或 SDK 回调均不直接标记公开发布成功；人工填写的链接与官方可验证结果应注明不同来源。
- 工作台不接管官方浏览器的登录会话，不提取其 Cookie。若以后采用手机交接，只传单份确认稿及必要媒体，使用短时、限权的交接凭证，避免暴露整个素材库。
- 后续接入官方授权渠道时复用统一的发布稿和审计记录。若平台没有提供幂等键或可靠结果查询，最终提交超时后必须暂停核实，不能以重试保证“恰好发布一次”。

人工通过官方渠道发布仍需满足账号状态、内容审核和媒体要求。这里的“更安全可靠”指减少非官方接口依赖、第三方会话托管和误发布，不承诺零风控或审核必过。
