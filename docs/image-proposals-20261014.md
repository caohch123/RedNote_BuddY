# 图片分析与三个建议方案：实现与验证

日期：2026-10-14。

## 本次改动

图片仿写第一步改为选择主图及可选参考图，然后明确点击“分析图片”。系统复用有效的视觉分析，并根据全部已选图片调用文本模型提出三个不同的建议。前端展示建议标题和具体修改说明，不默认选中；用户选择一个方向、填写可留空的附加要求后，才可生成提示词。后续审阅提示词、明确提交生图、保存素材库及采用结果的流程沿用现有实现。

建议按实际图片生成，不使用固定题材或预置的三套模板。内部控制仍区分主体、动作、背景、布局、配色、光影、画法及文字。后端检查建议数量、结构、来源和差异，并从持久化建议绑定控制项，不接受客户端伪造建议内容。附加要求仅对明确涉及的内容优先调整，其余部分继续遵循所选建议。

更换图片清除建议和选择；图片内容或模型配置变化时，旧建议不可用于编排。建议选择、附加要求和比例变化使提示词过期；清晰度和数量只调整生成设置。图片分析或建议失败保留已完成的分析，避免重试时重复调用有效图片分析。生成历史独立保存当时的建议、附加要求、实际提示词及图片顺序。

## 验证

- `go test ./... -count=1`：通过，包含后端、供应商适配和存储测试；仅使用模拟服务。
- 新增后端测试：无参考图及两张参考图均返回三个建议；分析全部已选图片；有效缓存复用；主动选择前不可编排；未知或过期建议拒绝；附加要求长度、清空和传递；图片及模型变化；推荐失败后重试保留视觉分析。
- 完整模拟流程通过：分析、选建议及附加要求、编排、用户明确提交、单张生成、重复请求去重、采用；实际提示词与审阅内容一致，图片顺序及尺寸正确，`prompt_extend:false`。生成前后发布素材及文案不变，采用仅替换主图位置，后续编辑不改写历史建议和附加要求。
- 新增供应商测试：一至三张图片角色和顺序正确；无效数量、重复建议、越界来源、缺失或多余字段拒绝；不完整分析不调用文本模型；附加要求优先级和长度校验。
- `npm test`：3 个文件、10 项测试通过。
- `npm run build -- --outDir dist-next`：TypeScript 检查及生产构建通过。

本地服务已更新到该实现。能力接口返回 `proposal_rules_version:1`、`proposal_count:3`，新版前端资源可通过 HTTP 正常读取。更新前确认两个工作区均无排队或运行任务；只重启工作台后端，原采集器进程继续运行。

本轮按用户要求暂不运行 Edge 验收，也没有调用真实图片模型。模拟服务验证接口、流程和请求内容，不作为最终图片质量合格的证据。

## 兼容

不迁移或覆盖既有方案、提示词、图片结果和发布内容。新增字段保存在现有 JSON 模型中，不需要数据库表迁移。旧的逐项控制及单图分析 API 保持兼容；新界面以三个建议和附加要求替代逐项编辑。仅点击“分析图片”才触发分析与建议任务，进入页面和普通保存不会调用模型。
