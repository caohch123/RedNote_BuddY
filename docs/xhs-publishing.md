# 小红书扫码登录与直接发布

在“发布管理”顶部使用“小红书发布账号”面板。点击“扫码登录小红书”，用本人小红书 App 扫描二维码，再在手机上确认。登录成功后，面板展示当前账号昵称与 ID。二维码过期可点击“重新获取二维码”。

选择图文或视频发布稿，点击“发布到小红书”。确认页展示实际账号、完整标题正文话题、素材顺序与可见性。选中核对复选框后，点击“确认发布到小红书”会实际上传素材并提交笔记。此前的查看、准备预览、导出和复制均不会发布。

发布任务单并发。已发布稿、正在发布的稿以及结果不明的稿不允许再次自动提交。失败时会保留发布错误，修改来源版本或账号设置后可重新准备。任务取得真实作品 ID 后自动保存链接与发布时间。

结果不明意味着最终请求可能已经到达平台。先打开小红书创作平台核对，确认作品存在时使用“记录已发布”填写作品链接；不要把结果不明视为一定没有发布。

## 数据与运行方式

- 参考 `cv-cat/Spider_XHS` 的本地 5.0.0 源码，使用独立 `publisher/.venv` 和固定的 Node 依赖。
- Gin 通过 stdin/stdout JSON RPC 管理一个本机发布进程，没有新增 HTTP 服务端口。
- 仅从二维码手机确认中取得登录会话；不会自动读取本地 Spider_XHS 的 `.env` 或已有账号。
- 登录凭据由后端 Windows DPAPI 保护，不返回前端、不放入任务快照和日志。
- 发布确认绑定账号、发布稿内容、文件 SHA-256 和可见性，五分钟有效并只能使用一次。
- 账号退出会清除本机登录会话。采集 Cookie 与创作平台发布会话独立。
- 来源清单与版本说明在 `publisher/upstream.lock.json` 和 `publisher/README.md`。

## 安装与检查

正常运行 `scripts/setup.ps1` 会安装发布依赖。单独准备发布运行环境：

```powershell
python publisher/prepare.py
.\scripts\doctor.ps1
```

运行环境为 Python 3.12+、Node.js 22+。组件不可用时界面显示待安装，已有浏览、编辑和导出功能仍可使用。

自动化测试使用模拟 RPC、平台响应和浏览器请求，覆盖二维码状态、确认步骤、会话保护、重复提交、未知结果与重启恢复。真实扫码需要本人在手机确认；真实提交由用户在确认页选择，不用模拟响应宣称实测发布成功。
