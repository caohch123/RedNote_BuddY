## 2. 已确认的技术事实

- 方案和历史批次中的特征映射一致：主图提供主体、场景、构图、光线和文字排版；辅助图只提供配色与画法材质。
- 生成快照中图片顺序是主图、辅助图，内容哈希与现有素材一致。未发现编号或数组顺序错位。
- 图片适配器将用户确认的最终提示词原样发出，使用参考图数组或原生多模态图片内容，显式设置 `prompt_extend: false`。未发现供应商二次扩写开关遗漏。
- 当前通用接口路径为兼容模式的 `/images/generations`；原生百炼地址使用 `/services/aigc/multimodal-generation/generation`。二者均携带图片进行编辑，代码没有单独的身份保持强度、蒙版或局部重绘参数。
- 用户当前失败结果属于已成功保存的图片请求；不要把工作流修复当作重发该请求的理由。

## 3. 根因

### 特征描述混入了其他维度

`scene` 混入“浅米色”“绿叶橙果”；`lighting` 混入“手绘温馨感”；`palette` 混入“浅蓝发色”“金色刺绣”；`texture` 混入“服装褶皱、蕾丝、毛边”。这些词同时描述主体身份、服装、颜色和画法，不能直接当作互相独立的来源约束。

### 最终提示词重复来源报告，保留了冲突

提示词先要求米色背景、绿色橙色边框、浅黄高亮和手绘感，最后再要求蓝白和数字插画。新增一句“以图片 2 为准”没有删除前面的冲突画面描述。辅助图的服装细节也被完整写入，图片模型因此有明确的女仆特征依据。

### “七项融合”缺少编辑意图

当前交互用同一种来源选择同时表达“替换人物”与“只换画法”。用户的这次意图是以主图为底图编辑，保留内容与空间关系；通用的七项自由融合并不自然表达“只允许改变外观”。

### 原有校验只证明了来源和字面覆盖

规则 4 可以发现来源映射改变或主体文字缺失，但无法证明角色身份保留、画面色彩统一、版式一致。返回自检布尔值也不能独立证明语义质量；图片质量仍需对照原图验收。

## 4. 实现验收建议

1. 默认提供“保留主图内容”编辑方式，把“自由融合特征”明确作为另一种方式。保留方式锁定主图的主体、场景对象、布局和已有信息结构，辅助图只能贡献外观。
2. 直接指定“数字插画”“蓝白配色”应优先于图片报告；其修改必须使现有提示词失效，且进入生成批次快照。
3. 先构建最终目标画面，再组织提示词。最终提示词必须只描述解决冲突后的状态，禁止逐段粘贴原报告后再追加优先级。
4. 辅助图提供画法时，不能把人物、女仆服、头饰、鲸鱼、动作或服装材质对象当作画法引入。提供配色时，应转成背景、基色、强调色关系。
5. 提示词应明确以图片 1 为底图，保留原人物身份、睡衣、睡觉动作，以及时钟、肝脏、装饰对象和布局。只改变画法与指定配色。不能仅检查是否出现“一位女性”。
6. 蓝白风是整体视觉目标；若支持自然肤色、头发等身份颜色例外，应明确其适用范围。按全文词表禁止一切非蓝白词属于有限防线，可能误伤保留人物身份的有效描述。
7. 自动测试覆盖冲突拒绝、辅助身份泄漏、来源越权、编辑意图失效、快照恢复、旧方案兼容及手动提示词审阅。模拟服务可以证明请求契约，不能证明真实模型画面质量。
8. 后续真实验收仅生成用户确认的少量图片，对照主图检查普通睡衣女性是否仍是同一人物、动作及关键对象是否保留、蓝白是否贯穿画面、女仆和鲸鱼服饰是否未进入结果。不以请求成功或尺寸正确代替视觉合格。
