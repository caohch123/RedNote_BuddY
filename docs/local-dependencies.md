# 本地依赖列表与路径一致性

设置页合并为一份“工具／用途／状态／可编辑路径”列表。FFmpeg负责抽帧、音轨、封面和播放副本，FFprobe负责视频探测，Node.js用于小红书签名；采集服务和数据库只显示状态，不重复提供安装或路径入口。窄屏每行排列为工具与状态、用途、路径，不增加横向或整页嵌套滚动。

## 运行规则

- `backend/internal/tooling` 统一解析、检测和执行。明确配置优先：完整路径直接使用，项目相对路径从项目根目录解析，程序名称从系统PATH解析。空路径自动查找PATH、项目工具目录及对应Windows安装位置。无效明确配置不会静默换用其他程序。
- FFmpeg／FFprobe的素材探测、转写、视频分析、生成结果处理及发布校验均使用相同解析器。Node.js配置用于小红书签名组件；Python签名与版本检查使用后端指定的同一可执行文件。
- 路径字段可清空为自动检测，PATCH中省略字段保持原值。保存Node.js路径后安全关闭旧账号组件，新组件按新路径启动并恢复已保存凭据；不会删除本机登录信息。账号操作正在执行时拒绝切换路径，以免打断发布。启动工作台不再因PATH中缺少Node而阻止用户进入设置配置自定义位置。
- 依赖检查实际执行`-version`或`--version`，有3秒超时、输出长度限制和隐藏窗口。拒绝目录、缺失文件、错误程序及Node.js低于22版本；不把任意程序输出作为错误信息。Edge只检查文件和组件，不启动浏览器。
- 数据库使用带超时的`SELECT 1`读取，采集服务检查本地接口。检查不调用AI、不登录或发布内容。未保存路径显示待保存；缺少检测结果显示未检查。版本信息随状态返回，只有配置与实际位置不同时补充解析位置。
- `doctor.ps1`在服务运行时复用同一个健康接口，安装／构建工具发现与实际运行工具分开显示；未启动时不把系统发现结果冒充已保存路径的检测结果。
